Where the port uses the source's transforms and layout glides, the traps they bring, and what is still an approximation; read before changing a popup entrance, a chevron, a thumb, a queued row or the home grid's re-slot.

## The rule

Port the source's transform on the same key, spring and `transform-origin`. A stand-in (a box property, a glyph swap) stays only where the source's mechanism cannot be expressed, and its drift entry names the exact gap rather than a generic cause. In place today: popup entrances (`y` and `scaleY` about the resolved side), tooltip chips and `followCursor`, dialog and command-menu panels (scale .97 about the centre), the mobile drawer, chevrons, switch and slider thumbs, the scroll-area thumb, radio dot, banner, chat-message, queued-stack and the callout pile, input-message tiles and queued rows, the input-copy glyph swap, the word roll, the fluid-hover cursor and distance label, the carousel fill, the skill page's press, cursor and timeline, the changelog dot and arrow, the file-thumbnail spinner, and the fluid highlight. A transform is also cheaper than the box property it replaces: a looping `top` or `width` is a whole frame, `x` / `y` / `translateX` is a patched tick.

Related capabilities in use: `filter` animates, so thinking-steps chips and images and the copy-prompt glyphs reveal on `blur(4px)`; `colorFade` and the theme-fade layer list `fill` and `stroke`, so SVG icons cross-fade with the page; a value spring ends on its target, so the banner's scale spring needs no `restDelta` / `restSpeed`.

## Traps

- **A transform changes what a measurement means.** `getBoundingClientRect` is the transformed box and nothing re-measures when a scale settles. See "Fluid hover" in [motion-and-fluid-hover.md](./motion-and-fluid-hover.md). The same rule is why `check-weight-widths` maps a scaling popup's content back through the popup's scale and holds a turning chevron to its centre.
- **A layout glide starts only for a move measured at a commit** (gpuix #113). The renderer compares a box's position across commits, so a layout that changes because an animation above it ticked, or because scroll anchoring adjusted, carries the box along and does not glide. `layout="position"` on ask-user-questions' footer buttons depends on this: the button beside a leaving one slides into its place while it fades.
- **A leaving `popLayout` child keeps its pin only while its style is stable** (#114). With a plain style object the tile row stays the positioned parent `popLayout` measures against, a removed tile or queued row leaves flow at once, and its siblings glide into place on `spring.fast`. The queue's 4 px spacing is the list's `gap`, because a per-row margin moves a sibling before it glides. A queued row still trails a region that moves it by a frame or two (the drift entry has the numbers).
- **An on-screen `layout` box makes every tick of a looping page whole (`Unsteady`).** Always-on `layout` on the bento cards took the showcase's idle CPU from 22% to 36%, so cards carry `layout` only while a `ResizeObserver` reports the grid resizing, switched on in the frame before the media query flips the columns. Giving `layout` in the same commit as the new columns glides nothing, so the columns are `createMediaQuery` state to keep the re-slot inside a commit. The price: a card that moves for another reason within 600 ms of a resize also glides. Queued-stack pays without a gate: `layout="position"` on the chat message idles it at 25-29% CPU with 0 patched frames (9.7% without), because the box never moves yet still counts as following the clock. That is a renderer question, not a port workaround (measured on gpuix `e31ec048`, October 2026).
- **One test renderer per thread.** A check that mounts a second root must unmount the first; `createCheck`'s unmount is idempotent for that reason. Otherwise a replaced root releases its Switch thumb's motion value against the newer renderer and dies with "unknown motion value" after every PASS.
- **A transformed box is its rounded layout position plus the exact translation, antialiased** (#109), so thumbs and text at a fractional translation sit at a sub-pixel position as in Chrome. Recaptured screenshots move slider and switch thumbs by up to half a pixel.
- **`check-table` reads layout counters, not retained builds**: the collapsed table's paint unit counts a retained build on every transform tick, which is not layout work.

## What is still an approximation

Each has a README gap row and a drift entry naming the exact gap; do not paper over them with a stand-in.

- **Size morphs.** `layout` and `layoutId` animate size as a scale about the box centre with radius and shadow corrected (#115), the source's projection, but a `layoutId` has no crossfade and no radius mix. The queued card's morph into its sent bubble is opaque from its first frame while the card plays its own exit under it, and a scroll between the commit and the glide's first frame shifts the start by the distance scrolled. `check-queued-morph` reads the transformed box mid-morph.
- **`var()` in a Motion key.** The source enters popups on `y: var(--popup-enter-y)`; gpuix substitutes `var()` only in the CSS transform properties, so a popup that flips starts its first open on the other side's 4 px slide (opacity 0 to 1 over 80 ms) and is right from the second open.
- **Text under an animating transform** is rasterized at a rounded-up scale and re-rasterized through the exact matrix when the run ends, as Chrome composites an animating layer, so a spring's last frames may shift a glyph by a pixel. Checks and screenshots read boxes at rest, where the matrix is exact.
- **The dropdown's RTL chevron mirror** is a port choice (no direction context), not a gpuix gap.
